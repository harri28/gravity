# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project Overview

**Gravity** is a pharmacy Point of Sale (POS) web application built with PHP, vanilla JavaScript, and PostgreSQL. It runs on XAMPP (Apache + PHP).

## Running the Application

**Prerequisites**: XAMPP with Apache running, PostgreSQL running with the database initialized.

**Database setup** (first time only):
```bash
psql -U postgres -c "CREATE DATABASE farmacia;"
psql -U postgres -d farmacia -f database/schema.sql
```

**Entry point**: `http://localhost/farmacia/modules/ventas/index.php`
There is no root `index.php` — navigating to `/farmacia/` will 404.

**Database credentials** in `config/database.php`: host `localhost:5432`, db `farmacia`, user `postgres`, pass `1234`.

There is no build step, no package manager, and no test runner.

## Architecture

### Request Flow
```
Browser → PHP page (modules/ventas/*.php) → includes header/footer
              ↓
         Vanilla JS makes fetch() calls
              ↓
         modules/ventas/api.php?action=<name>
              ↓
         PDO queries via config/database.php getDB()
              ↓
         JSON response
```

### Page Convention
Every PHP page must set these variables **before** `include '../../includes/header.php'`:
- `$base_path` — relative path back to project root (e.g. `'../../'`), used by header for asset/nav URLs
- `$current_module` — controls sidebar active state (e.g. `'ventas'`)
- `$current_page` — controls sub-nav active state (e.g. `'pos'`, `'historial'`, `'favoritos'`)
- `$page_title` — HTML `<title>`
- `$breadcrumb` — topbar breadcrumb HTML string

### Key Files
- **`config/database.php`** — PDO singleton (`getDB()`), plus shared utilities: `jsonResponse()`, `formatMoney()`, `generarNumeroVenta()`, `generarNumeroIngreso()`
- **`modules/ventas/api.php`** — Single-file REST API dispatcher; routes via `?action=`: `productos`, `buscar_cliente`, `registrar_venta`, `anular_venta`, `historial`, `detalle_venta`, `stats_dia`, `top_vendidos`, `favoritos`, `toggle_favorito`
- **`modules/ventas/index.php`** — Full POS interface (product grid, cart, payment modal, ticket modal)
- **`modules/ventas/historial.php`** — Sales history with date/status filters and sale cancellation
- **`modules/ventas/favoritos.php`** — Analytics: top-selling products, revenue by category
- **`includes/header.php`** — Outputs full `<html><head>`, sidebar, topbar, and opens `<main>`
- **`includes/footer.php`** — Closes `<main>`, outputs sidebar toggle JS and date display
- **`assets/css/style.css`** — Complete design system using CSS custom properties (`--primary`, `--surface-2`, etc.)

### Database Schema (PostgreSQL)

Tables by module:
- Core: `categorias`, `productos`, `clientes`, `cajas`, `ventas`, `venta_detalles`
- Almacén: `proveedores`, `ingresos`, `ingreso_detalles`
- Caja: `caja_movimientos`
- Facturación: `comprobantes_electronicos`, `series_comprobantes`

Key behaviors:
- Sale number format: `V20260317-0001` (generated by `generarNumeroVenta()`); ingreso format: `I20260317-0001`
- Sale status values: `completada`, `anulada`, `pendiente`
- Payment methods: `efectivo`, `yape`, `plin`, `tarjeta`, `transferencia`
- Stock is decremented on sale (`registrar_venta`) and restored on cancellation (`anular_venta`); `total_vendido` on `productos` is incremented on sale but **not** decremented on cancellation
- PostgreSQL returns boolean columns as the string `'t'`/`'f'` in PDO — the JS in `index.php` checks `p.favorito == 't'` for this reason
- All sale/ingreso mutations use `PDO::beginTransaction()` with rollback on failure
- Caja must be opened (`aperturar`) before sales can be registered; the `cajas` table tracks open/closed sessions with `estado = 'abierta'`

### Modules Status

- **Planned/disabled in UI**: Compras, Facturación (sidebar items show "Pronto" badge)

### Additional Files
- **`config/nubefact.php`** — Nubefact API integration for SUNAT electronic billing. Contains `enviar_nubefact()`. Prices are IGV-inclusive; `valor_unitario = precio / 1.18`. Correlative numbers tracked in `series_comprobantes` table (B001 boletas, F001 facturas).
- **`assets/js/barcode-scanner.js`** — Global HID keyboard barcode scanner detection. Included in `header.php`. Fires `CustomEvent('barcodescan', { detail: { code } })` on `document`. Uses keystroke timing: < 50ms between chars + Enter + ≥ 3 chars = scan event.
- **`test/facturacion_test.php`** — Standalone RUC/DNI lookup test page using Nubefact API + apis.net.pe fallback.

### API Modules
Each module has its own `api.php` with a `switch ($action)` dispatcher:
- `modules/ventas/api.php` — `productos`, `buscar_cliente`, `registrar_venta`, `anular_venta`, `historial`, `detalle_venta`, `stats_dia`, `top_vendidos`, `favoritos`, `toggle_favorito`
- `modules/inventario/api.php` — `stats`, `listar`, `categorias`, `crear`, `actualizar`, `ajustar_stock`, `toggle_activo`
- `modules/almacen/api.php` — `proveedores_listar`, `proveedor_crear`, `proveedor_actualizar`, `proveedor_toggle_activo`, `stats_almacen`, `ingresos_listar`, `ingreso_detalle`, `buscar_producto`, `registrar_ingreso`, `anular_ingreso`
- `modules/caja/api.php` — `estado`, `usuarios`, `aperturar`, `cerrar`, `registrar_movimiento`, `movimientos`, `historial`
